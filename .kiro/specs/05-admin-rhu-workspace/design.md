## 2. Data

### 2.1 `src/shared/services/apiAdmin.ts` (new)

```ts
fetchAllAppointments(limit = 500): Promise<Appointment[]>
fetchCarePlans(patientId?: string): Promise<CarePlan[]>          // clinician only
assignHelpRequest(id, bhwId): Promise<HelpRequestRow>             // update … neq completed, select → maybeSingle; null → throw
reassignPatient(patientId, bhwId): Promise<{ movedRequests: number; movedAppointments: number }>
saveCarePlanDraft(input): Promise<CarePlan>                        // update where status='draft', else insert draft
releaseCarePlan(input): Promise<CarePlan>                          // see 2.3
```

`assignHelpRequest` sets `assigned_bhw_id`, `coordination_status: 'assigned'`, `acknowledged_at: null`.
`reassignPatient`: (1) `patients.update({ bhw_id, updated_at })` with `.select('id')` → must return a row; (2) `help_requests.update(...)` where `patient_id = p` and `coordination_status in (unassigned, assigned, acknowledged, blocked)`; (3) `appointments.update({ owner_bhw_id, updated_at })` where `patient_id = p` and `encounter_status in (requested, confirmed)`. Each step `.select('id')` for counts. Steps are idempotent, so a partial failure is fixed by retrying.

### 2.2 Coordinator data (`useAdminData`, extended)

Adds `appointments` to the parallel fetch and the cache (`admin:<id>`; old caches default to `[]`). Drops `computeMetrics`/`HealthMetrics` and `HealthMetricsGrid` (K4). `helpRequests` limit raised to 200 so metrics see all open tasks. Dedupe by id is kept.

### 2.3 Clinician data (`useClinicalReview(enabled)`)

When `enabled` is false: returns `{ data: null }` and makes no request. When true: fetches patients, `fetchRecords({ limit: 500 })`, `fetchCarePlans()`; cache-then-network under `admin:clinical:<clinicianId>`.

Release (`releaseCarePlan`), plan id generated by `newId()` when the form opens:
1. `update({...fields, status:'released', released_at: now})` where `id` and `status='draft'` → select.
2. If no row: `upsert({...released row}, { onConflict:'id', ignoreDuplicates:true })`, then read back by id. `status !== 'released'` → throw.
3. `records.update({ review_status:'plan_released' })` where `patient_id` and `review_status='awaiting_clinical_review'`.
4. `patients.update({ yakap_stage:'plan_available' })` where `id` and `yakap_stage='results_review_pending'`.

Every step is idempotent; on error the form keeps its text and shows the error with Release still available.

## 3. Pure logic (no React, testable with `npx tsx`)

### 3.1 `src/features/admin/needsAttention.ts`

```ts
INACTIVE_DAYS = 3; REVIEW_OVERDUE_DAYS = 3; BLOCKED_OVERDUE_DAYS = 7
isBHWInactive(bhw, now), isActiveOwner(bhwId, bhws, now)
buildNeedsAttention({ bhws, patients, records, helpRequests }, now): NeedsAttention
```

`NeedsAttention` = `{ unassignedRequests, unassignedPatients, overdueReviews, blockedRequests, newerBlockedCount, inactiveBHWs }`, each item `{ id, ageMs, ... }`, sorted oldest first. A patient is unassigned when `bhw_id` is null or not a known BHW. Review age = `now - (created_at)` (received time). Blocked age = `now - received_at`. Inactive age = `now - last_active_at` (null for never).

### 3.2 `src/features/admin/summaryMetrics.ts`

```ts
type PeriodDays = 30 | 90 | 180
computeSummary({ patients, appointments, records, helpRequests, bhws }, period, now): SummaryMetrics
```

Each metric: `{ key, label, numerator, denominator, unknown, period, cohort, unknownNote, cases: MetricCase[] }`. Follow-up also returns `breakdown: { completed, missed, rescheduled, unknown }`; `assertBreakdown` checks the sum equals the denominator, otherwise the screen shows a warning instead of the breakdown.

Bucketing for appointments due in period (scheduled_at in [now − period, now]): `clinic_confirmed_attended` → completed; `missed` → missed; `rescheduled` → rescheduled; everything else (`requested`, `confirmed`, `patient_reported_attended`) → unknown.

First checkup per cohort patient: `confirmed` if any appointment is `clinic_confirmed_attended` or the stage ∈ {tests_requested, results_review_pending, plan_available, continued_monitoring}; else `unknown` if any appointment is `patient_reported_attended` or a `requested/confirmed` one is past due; else `not_yet`.

## 4. Components (`src/features/admin/components`)

| Component | Purpose |
|---|---|
| `QueueTable` | `columns: { key, label, flex }[]`, `rows: { id, cells: Record<key, ReactNode> }[]`, `empty`. `useWindowDimensions().width >= 768` → header + row grid; else card with "Label: value" lines. |
| `AssignSheet` | Modal sheet like ConfirmSheet: title, current owner, ChipGroup of available BHWs, an optional note (cascade counts), Assign + Cancel, busy and error. Escape/back/backdrop close. |

| `MetricCaseList` | Cases for the selected metric with chips. Follow-up grouped by bucket. |
| `CarePlanForm` | Patient's latest readings (MeasurementCard), pending results, existing plans with status, TextFields summary/next steps, no-diagnosis reminder, Save draft / Release (ConfirmSheet). |

## 5. Screens

- **NeedsAttentionScreen.** Header subtitle `Carmen Reyes (DEMO) · coordinator`. Error / loading / cached notice. Five sections (QueueTable each) with ages via `formatAge(ms)` ("6 days", "3 hrs"). Actions: Assign → AssignSheet; Open Clinical Review → `router.push('/admin/clinical-review')`; Reassign (blocked) → AssignSheet; Reassign patients → `router.push({ pathname: '/admin/patient-management', params: { bhw } })`. Then `DemoClinicInbox`, `FieldRecordsFeed`, BHW roster (no ranking), ConnectionTest.
- **AssignmentsScreen.** Optional `bhw` filter chip row (with "All"). Section "Patients" (name, barangay, owner + inactive marker, open tasks count, Reassign/Assign). Section "Open help requests" (patient, reason, received, owner, chip, Reassign). Unassigned rows first. Patient reassign confirm note: "Also moves N open help requests and M open appointments."
- **SummaryScreen.** Period ChipGroup. Four Pressable MetricTiles (`accessibilityRole="button"`, selected state). Note A-3.5/6. Freshness via LastUpdated / "Data as of". Selected metric → MetricCaseList + follow-up breakdown row.
- **ClinicalReviewScreen.** `clinicianMode` from `useDemoRole()`. Off → EmptyState "Restricted clinician view" + explanation and how to turn on Clinician mode. On → simulated-role notice, review queue (QueueTable + "Review" action selecting the patient), patient picker (ChipGroup), CarePlanForm.

## 6. Offline and errors

`useConnectivity().isOnline === false` → actions disabled with "Assigning needs a connection." (clinician: "Releasing a plan needs a connection."). Load failures: cache fallback with LastUpdated; no cache → error Notice + EmptyState.
